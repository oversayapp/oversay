# Security audit before the 0.5.0 release, November 2026

Run on 2026-11-21 against `main` at commit `56e1746` (version 0.5.0), as `docs/releasing.md` step 2 asks. The raw notes of the run are kept outside the repository; this is its summary.

**A focused read of the code added since 0.4.0, by one agent in one pass: partial coverage, not a clean bill of health.** It was not an independent multi-agent audit like many a full run, and no finding was verified by a second reader.

## Result

| | |
|---|---|
| Confirmed | 0 |
| Needs validation | 1 lead, **low** |
| Hardening notes | 3 |

## Covered (read in full or in the parts that matter)

- **Sign-in** (`account/mod.rs`, `account/keychain.rs`, `links.rs`): PKCE verifier and `state` made from 32 random bytes and kept in memory for ten minutes; the `state` compared in constant time and used once (a second link with it is refused while the code is traded); `oversay://auth` links go to the account and never to the manager; the refresh token and email live only in the OS keychain, one item per stage; tokens are in a type whose `Debug` hides them and are not logged. The stage is chosen when the app is built (`prod` for a release build, `dev` for a debug build), and no runtime or user input picks it.
- **Sync to and from the cloud** (`sync/library.rs`, `sync/cloud.rs`): an id from the cloud becomes part of an API path only after it passes `is_valid_id`; a deck folder made from a cloud title goes through `folder_name` (no separators, control characters, `$`, backticks, reserved Windows names; 80 characters); a deck or workspace whose own text names another id is not written; links are never followed or written through; edits since the last scan are never overwritten or trashed; a scan that couldn't read everything deletes nothing; responses are size-limited and every request has a timeout; only `deck.md`, `sessions.json` and `workspace.json` are read or written.
- **Capabilities** (`capabilities/*.json`, `build.rs`): the new commands are each allowed one by one, and the terms and privacy pages are the only new links the manager may open.
- **One-time resources move** (`resources_move.rs`): nothing is overwritten (`free_path`), the original is removed only after every copy is made, and a manifest lets Undo put it back.
- **Skill zips** (`skill.rs`): written from the bundled skill folder only.

## Not covered

The Svelte front end (Account, Library, deck editor, Sessions, rail), `tray.rs`, `tray_menu.rs`, `control_panel.rs`, `overlay.rs`, `session.rs`, `example_decks.rs`, the sync round scheduler and saver (`sync/mod.rs`, `sync/saver.rs`), the transport and TLS set-up (`account/cognito.rs`), and the web-api service itself (a separate private repository). The unvalidated and deferred areas of the 0.4.0 audit remain deferred.

## Lead (low): an alias in a deck's resources is lost by the one-time move

`resources_move.rs` `move_up` copies each entry with `copy_tree`, which skips a symbolic link ("left behind", its comment says), and then calls `remove_any` on the source. For a link that sits directly in a deck's `resources/`, nothing is copied and the link itself is removed, so the alias is gone and Undo can't restore it (the recorded copy doesn't exist). The link's target is not touched. Impact: a person loses a shortcut they made by hand. Not exploitable. Not reproduced. It does not block the tag; John decides whether to fix it.

## Hardening notes

1. The ID token's email is read without checking its signature (OIDC Core §3.1.3.7 allows this for a token received straight from the token endpoint over TLS). It is shown only as a label; nothing is authorized by it.
2. `scripts/update-test.sh` makes a release build, so it now signs in to `prod` unless run with `OVERSAY_ACCOUNT_STAGE=dev` (noted in PR 86).
3. The release build still contains the `dev` stage's public identifiers (pool, client id, API). They are not secrets.
