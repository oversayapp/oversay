# Security audit before the 0.6.0 release, November 2026

Run on 2026-11-25 against `main` at commit `b0671bc` (version 0.6.0), as `docs/releasing.md` step 2 asks. The raw notes of the run are kept outside the repository; this is its summary.

**A focused read of the code changed since 0.5.0, by one agent in one pass: partial coverage, not a clean bill of health.** It was not an independent multi-agent audit, no finding was verified by a second reader, and nothing was run in the app.

## Result

| | |
|---|---|
| Confirmed | 0 |
| Needs validation | 0 |
| Hardening notes | 1 |

The 0.5.0 audit's low lead (the one-time resources move lost an alias) is fixed by [#92](https://github.com/oversayapp/oversay/pull/92), by reading the code; no alias was tried in the running app.

## Covered

- **Permissions:** one new command, `set_edit_menu`, allowed in the manager window's capability only. No new link, plugin or content security policy change.
- **Mac Edit menu** (`edit_menu.rs`, `platform.rs`, `edit-menu.ts`): its item ids don't collide with the tray's, the page checks the event's value, and the one new `unsafe` block sends `undo:` or `redo:` on the main thread inside an Objective-C exception catch.
- **Resources move** (`resources_move.rs`): the alias check does not follow links, and an entry holding one is neither copied nor removed.
- **Deck editor and session page** (the changed TypeScript and Svelte, tests and styling aside): no new HTML injection, no new link or network request, and the clipboard gets only the review request, as before. Undo history stays in memory and is dropped when text comes in from outside. New log lines carry positions and states, not what was written or said, and are written in development builds only.
- **Dependencies:** `npm audit` found nothing; `cargo audit` found no vulnerability and printed six allowed warnings (five unmaintained crates, one unsound in `glib`).
- **Secrets:** gitleaks over every local and fetched branch and tag (763 commits) found nothing. The separate scan of merge conflict resolutions was not repeated.
- **Build workflow:** unchanged since 0.5.0.

## Not covered

Code that did not change since 0.5.0, the CSS, `scripts/screenshots.mjs` beyond a keyword search (it is not shipped), and the web-api service (a separate private repository). What the 0.4.0 and 0.5.0 audits left uncovered or deferred was not revisited, nor were the 0.5.0 audit's hardening notes.

## Hardening note

1. As in 0.5.0, an error part-way through the one-time resources move returns before the Undo record is written. Nothing is lost (each original is removed only after its copies are made), but what had already moved can't be undone from the note.
